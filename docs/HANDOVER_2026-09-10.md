### Milestone G: groups and leaderboard (next, 1–2 days)
Tim: "je kan groepen maken waarbij je de counter kan bijhouden hoeveel bier er wordt gelogd,
zodat je ook kan battelen tegen andere groepen; er is een leaderboard-pagina waar je kan zien
welke groepen er zijn en hoeveel er deze dag al gelogd is."
- Data: `groups/{id}` {name ≤ 30, code (6 chars, join), createdBy, createdAt, memberCount, todayDate, todayCount, totalCount}; `groups/{id}/members/{uid}` {joinedAt}; `users/{uid}/private/groups` mirror or a collection-group query on members. A user can be in several groups; a drink counts for every group the owner is in (server: `onBeerCreated` increments each group's `todayCount` with a day rollover in the same transaction; `cleanupExpired`'s daily run resets nothing, the rollover handles it).
- Rules: anyone signed in can read groups (leaderboard is public inside the app); create by any signed-in user (creator becomes member); join by code via callable `joinGroup` (rules keep members create-only by the server); leave = delete own member doc; counters server-only.
- App: new **Groups** tab (replaces nothing; 5 tabs is the HIG max: Beers, Mates, Map, Groups, Settings). Screens: leaderboard (all groups sorted by todayCount, then totalCount; my groups pinned on top with a crown for #1), group detail (members, today/total, invite by code + share link `https://beerwithme-prod.web.app/join/<code>` → universal link), create group sheet (name), join by code sheet. Push: none by default (a group push on every drink would be spam); optional later: "your group took the lead".
- Copy: "beer" counter counts pils + special only? Decide: count ALL drinks but show "🍺 today" as the label; Tim to confirm.
- Tests: BeerKit (view model for leaderboard sorting), emulator (rules, join/leave, counter rollover), rig screenshot of the leaderboard with two seeded groups.
- Process: plan → shared layer (Claude) → 2 Opus workers (leaderboard/detail, create/join sheets + shell) → Fable finish review → fix round → rig → build → mates.
